# 功能规格说明书（Spec）

| 项目 | 内容 |
| --- | --- |
| 系统名称 | 采购审批中心 ProcureFlow |
| 文档版本 | v1.0 |
| 编写日期 | 2026-10 |
| 评审状态 | 已完成设计评审（见《05-审查报告》） |
| 适用范围 | 企业采购申请 → 主管审批 → 财务复核 全流程 |

---

## 1. 背景与目标

企业采购审批的核心诉求是**"在正确的节点，由正确的人，做出可追溯的决定"**。本项目将该诉求拆解为三个可验证的目标：

| 编号 | 目标 | 验收方式 |
| --- | --- | --- |
| G1 | 审批链随金额自动路由，规则不依赖人工判断 | 边界用例：4999.99 / 5000.00 / 5000.01 |
| G2 | 越权操作在服务端被拦截，而非仅隐藏前端按钮 | 越权用例直接调用接口，断言 403 |
| G3 | 同一单据不会因并发产生重复审批记录 | 并发用例：两个线程同时审批，断言仅一条流水 |

## 2. 名词定义

| 术语 | 含义 |
| --- | --- |
| 申请单 | 一次采购请求的载体，含标题、事由、类别、金额、部门、申请人 |
| 审批节点 | 单据当前等待处理的角色，取值为"部门主管"或"财务" |
| 终态 | 已通过 / 已驳回 / 已作废，终态单据不可再变更 |
| 数据范围 | 某角色在列表中可见的单据集合，由角色与归属关系共同决定 |
| 自审自批 | 审批人审批自己提交的单据，本项目明确禁止 |

## 3. 角色与权限矩阵

| 操作 | 员工 EMPLOYEE | 部门主管 MANAGER | 财务 FINANCE | 管理员 ADMIN |
| --- | --- | --- | --- | --- |
| 创建申请单 | ✅ | ❌ | ❌ | ❌ |
| 编辑草稿 | 仅本人 | ❌ | ❌ | ❌ |
| 提交审批 | 仅本人 | ❌ | ❌ | ❌ |
| 审批·主管节点 | ❌ | ✅ 仅本部门且非本人 | ❌ | ❌ |
| 审批·财务节点 | ❌ | ❌ | ✅ | ❌ |
| 驳回 | ❌ | ✅ 同上 | ✅ | ❌ |
| 作废 | 本人未终态单据 | ❌ | ❌ | ✅ 任意未终态单据 |
| 列表可见范围 | 仅本人 | 本部门全部 | 全部非草稿 | 全部 |
| 查看详情 | 本人 | 本部门 | 非草稿 | 全部 |

> 说明：管理员只具备"可见 + 作废"，**不具备审批权**。审批权与业务职责绑定，不能由系统管理员代行。

## 4. 业务流程与状态机

```
                    ┌─────────┐
                    │  DRAFT  │ 草稿
                    └────┬────┘
                  submit │
                         ▼
                ┌──────────────────┐
                │ PENDING_MANAGER  │ 待主管审批
                └────┬─────────┬───┘
        approve(<5000)│         │approve(>=5000)
                      │         ▼
                      │  ┌──────────────────┐
                      │  │ PENDING_FINANCE  │ 待财务复核
                      │  └────┬─────────────┘
                      │       │ approve
                      ▼       ▼
                    ┌────────────┐
                    │  APPROVED  │ 已通过（终态）
                    └────────────┘

  任意非终态 --reject--> REJECTED（终态）
  任意非终态 --cancel--> CANCELLED（终态）
```

**状态取值**

| 状态 | 中文 | 是否终态 | 进入条件 |
| --- | --- | --- | --- |
| DRAFT | 草稿 | 否 | 员工创建 |
| PENDING_MANAGER | 待主管审批 | 否 | 员工提交 |
| PENDING_FINANCE | 待财务复核 | 否 | 主管通过且金额 ≥ 5000 |
| APPROVED | 已通过 | 是 | 末级审批通过 |
| REJECTED | 已驳回 | 是 | 任一审批人驳回（须填原因） |
| CANCELLED | 已作废 | 是 | 申请人撤回或管理员作废 |

## 5. 功能需求

### FR-01 登录与身份识别

- 用户以用户名 + 密码登录，成功后返回令牌与用户信息（姓名、部门、角色）。
- 后续请求通过 `Authorization: Bearer <token>` 识别身份。
- **验收标准**：错误密码返回 `400`；无令牌访问受保护接口返回 `401`；令牌 8 小时后过期。

### FR-02 创建申请单

- 字段：标题（必填，≤120 字）、事由（必填，≤500 字）、类别（必填，枚举）、金额（必填，>0，最多两位小数）。
- 初始状态 `DRAFT`，单号自动生成 `PR{yyyyMMdd}-{4位流水}`，部门与申请人取自当前登录用户（**不接受前端传入**，防止伪造归属）。
- **验收标准**：仅 `EMPLOYEE` 可创建，其他角色返回 `403`；空标题或负金额返回 `400` 且提示具体字段。

### FR-03 编辑草稿

- 仅申请人本人、且状态为 `DRAFT` 时可编辑。
- **验收标准**：非本人编辑返回 `403`；非草稿状态编辑返回 `409`。

### FR-04 提交审批

- `DRAFT → PENDING_MANAGER`，写入一条 `SUBMIT` 流水。
- **验收标准**：重复提交返回 `409`；非本人提交返回 `403`。

### FR-05 主管审批

- 前置条件：状态为 `PENDING_MANAGER`，操作者为**同部门** `MANAGER`，且不是申请人本人。
- 结果分支：
  - 金额 `< 5000` → `APPROVED`
  - 金额 `>= 5000` → `PENDING_FINANCE`
- **验收标准**：跨部门主管返回 `403`；自审自批返回 `403`；`4999.99 → APPROVED`、`5000.00 → PENDING_FINANCE`、`5000.01 → PENDING_FINANCE`。

### FR-06 财务复核

- 前置条件：状态为 `PENDING_FINANCE`，操作者为 `FINANCE`。
- 通过后 → `APPROVED`。
- **验收标准**：财务审批 `PENDING_MANAGER` 状态的单据返回 `403`。

### FR-07 驳回

- 前置条件：与当前节点审批权一致；**必须填写驳回原因**。
- 结果：当前状态 → `REJECTED`。
- **验收标准**：原因为空返回 `400`；驳回后单据为终态，不可再审批。

### FR-08 作废

- 申请人可作废本人未终态单据；管理员可作废任意未终态单据。
- 结果：→ `CANCELLED`，记录作废原因（默认"申请人撤回"）。
- **验收标准**：终态单据作废返回 `409`；非本人且非管理员返回 `403`。

### FR-09 列表查询与数据范围

- 参数：`tab`（`mine` / `todo` / `all`）、`status`、`category`、`keyword`、`page`、`size`。
- `todo` 语义：主管 = 本部门待我审批且非本人；财务 = 全部待财务复核；员工 = 空集。
- **验收标准**：员工调用 `tab=all` 仍只能看到本人单据；关键字匹配标题或单号，忽略大小写。

### FR-10 详情与审批时间线

- 返回单据全量字段 + 按时间正序的审批流水（操作人、角色、动作、状态变更、意见、时间）。
- **验收标准**：无权限查看返回 `403`；流水条数与实际操作次数一致。

### FR-11 工作台统计

- 指标：待我处理、我的进行中、可见单据、本月已通过金额、各状态数量分布、各类别已通过金额。
- **验收标准**：统计口径与列表 `total` 一致（同一数据范围）。

### FR-12 并发控制与重复审批防护

- 两人同时审批同一单据时，**仅一人成功**，另一人收到 `409`，且不产生第二条审批流水。
- **验收标准**：并发用例断言"成功 1 次 + 失败 1 次 + APPROVE 流水 1 条"。

## 6. 非功能需求

| 编号 | 类别 | 要求 | 落地方式 |
| --- | --- | --- | --- |
| NFR-01 | 安全 | 鉴权与授权分离；越权必须服务端拦截 | 拦截器做认证，Service 做授权与数据范围过滤 |
| NFR-02 | 一致性 | 状态变更与流水写入在同一事务 | `@Transactional` 包裹写操作 |
| NFR-03 | 并发 | 同一单据不得重复审批 | 实体 `@Version` 乐观锁 + 409 语义 |
| NFR-04 | 可维护 | 审批规则集中，可独立测试 | 抽出 `ApprovalPolicy` 组件 |
| NFR-05 | 可配置 | 金额阈值不写死在代码里 | `application.yml` → `AppProperties` |
| NFR-06 | 可追溯 | 所有状态变更留痕，只增不改 | `approval_record` 表 |
| NFR-07 | 性能 | 列表分页，单页不超过 100 条 | 服务端强制 `size ≤ 100` |
| NFR-08 | 可移植 | 单端口部署，零外部依赖 | 前端产物打入 jar，H2 内存库 |
| NFR-09 | 编码 | 全链路 UTF-8 | 编译与 HTTP 编码统一配置 |

## 7. 边界与异常场景

| 场景 | 期望行为 | 覆盖用例 |
| --- | --- | --- |
| 金额恰为 5000.00 | 进入财务复核 | `exactlyThresholdRequiresFinance` |
| 金额 4999.99 | 主管终审 | `belowThresholdGoesStraightToApproved` |
| 金额为 0 / 负数 | `400`，提示"金额必须大于 0" | `invalidPayloadReturns400` |
| 金额三位小数 | `400`，提示"最多两位小数" | 参数校验 |
| 标题为空 | `400`，提示"标题不能为空" | `invalidPayloadReturns400` |
| 驳回不填原因 | `400`，提示"驳回必须填写原因" | `rejectWithoutReasonReturns400` |
| 重复审批已终态单据 | `409` | `approveTerminalRequestReturns409` |
| 跨部门主管审批 | `403` | `crossDepartmentApproveForbidden` |
| 员工调用审批接口 | `403` | `employeeApproveForbidden` |
| 财务查看员工草稿 | `403` | API 校验脚本 |
| 无令牌访问 | `401` | `missingTokenUnauthorized` |
| 两人同时审批 | 一人成功、一人 `409` | `concurrentApproveOnlyOneWins` |

## 8. 本期不做（Out of Scope）

明确划出边界，避免"什么都想做什么都做不深"：

- 组织架构与人员管理（部门、汇报关系维护）
- 附件上传与发票影像
- 预算额度扣减与占用
- 审批链可视化配置（多级、会签、或签）
- 消息通知（邮件 / 企业微信 / 站内信）
- 单点登录与第三方账号体系
- 数据导出（Excel / PDF）

> 以上功能在架构上均预留了扩展点，见《02-架构设计》第 7 节。
