# 项目介绍

## 一、项目名称

**采购审批中心（ProcureFlow）** —— 企业采购申请与分级审批平台

## 二、业务场景

中大型企业的采购不是"谁需要谁去买"，而是一条受控的流程链：员工提出申请 → 部门主管审核业务必要性 → 财务复核预算与合规 → 归档留痕。

这条链路在真实企业里有三个绕不开的痛点：

| 痛点 | 具体表现 | 本项目的应对 |
| --- | --- | --- |
| 审批规则靠人记 | 多少钱该找谁签？5000 元到底要不要财务？口头规则经常执行走样 | 规则代码化、阈值可配置，`>= 5000` 这类边界写进单元测试 |
| 权限边界模糊 | 前端把按钮藏了，接口却没校验，改个请求就能越权审批 | 权限判断下沉到服务层，前端隐藏按钮只是体验优化 |
| 重复审批与扯皮 | 两个人同时点"通过"，产生两条审批记录，事后无法追溯 | 实体乐观锁 + 审计流水，并发时只允许一人成功 |

## 三、核心功能

1. **申请单管理**：创建、编辑草稿、提交、作废；单号自动生成（`PR + 日期 + 流水`）。
2. **金额分级审批**：`< 5000` 元主管一级终审；`>= 5000` 元主管通过后自动进入财务复核。
3. **角色 + 数据范围双重控制**：员工看自己、主管看本部门、财务看全量非草稿、管理员看全部。
4. **审批留痕**：每一次状态变更（创建/提交/通过/驳回/作废）写入 `approval_record`，只增不改。
5. **并发安全**：两人同时审批同一张单，仅一人成功，另一人收到 `409` 明确提示。
6. **工作台**：待我审批 / 全部申请 / 我的申请三个视图，配统计卡片（待办数、进行中、可见单据、本月已通过金额）。

## 四、案例特点

这个案例不是"用 AI 写个增删改查"，而是刻意选择了一个**规则密集、边界敏感**的业务：

- **有真实业务复杂度**：状态机 6 个状态、4 种角色的数据范围、金额阈值分级，任何一处写错都能被测试抓出来。
- **能演示"AI 生成 + 人工校验"的闭环**：需求 → 设计 → 编码 → 测试 → 审查，每一步都有可核对的产出物。
- **可量化**：19 个 JUnit 用例 + 26 项接口校验，覆盖权限、边界、并发、参数校验。
- **可部署**：前端产物打进 Spring Boot 静态资源，单端口单 jar，一条命令即可在任何云主机跑起来。

## 五、技术栈

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Java 17 + Spring Boot 3.3.5 | Web / Data JPA / Validation |
| 数据库 | H2（内存，MySQL 兼容模式） | 演示零依赖；生产可平滑替换 MySQL |
| 前端 | Vue 3.5 + Vue Router 4 + Vite 5 | 组件自研，不引入 UI 库，构建产物体积小 |
| 鉴权 | Bearer Token（内存会话） | 演示用简化方案，生产应替换为 JWT / Redis |
| 测试 | JUnit 5 + MockMvc + AssertJ | 单元测试 + 集成测试 + 并发测试 |
