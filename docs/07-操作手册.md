# 操作手册

本手册覆盖三件事：**本地怎么跑起来**、**怎么演示**、**怎么部署到公网**。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+ | 项目使用 Java 17 语法（record / switch 表达式） |
| Maven | 3.6+ | 或用 IDE 内置 Maven |
| Node.js | 18+ | 仅前端二次开发需要；只跑后端不需要 |
| 浏览器 | Chrome / Edge 最新版 | 界面使用现代 CSS（grid、backdrop-filter） |

> 数据库无需安装：默认使用 H2 内存库，启动即初始化演示数据。

## 2. 最快启动（直接用打好的 jar）

```bash
java -jar purchase-approval-1.0.0.jar
```

看到下面这行即启动成功：

```
Started PurchaseApplication in 3.2 seconds
```

浏览器打开 <http://localhost:8080>，用任意演示账号登录。

> jar 已内嵌前端产物，**不需要单独启动前端**。

## 3. 从源码启动

```bash
# 1) 打包（会自动执行测试）
mvn clean package

# 2) 运行
java -jar target/purchase-approval-1.0.0.jar

# 或者跳过测试直接跑
mvn spring-boot:run
```

## 4. 前端开发模式（需要改界面时）

前端源码在 `frontend/`，构建产物输出到后端静态目录。

```bash
cd frontend
npm install          # 首次
npm run dev          # 开发服务器 http://localhost:5173，/api 自动代理到 8080

npm run build        # 产物输出到 ../src/main/resources/static
```

修改前端后必须重新 `npm run build` 并重新打包 jar，改动才会体现在单端口部署里。

## 5. 演示动线（建议 5 分钟）

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `zhangwei` 登录 | 员工只能看到自己的 5 张单，看不到市场部 |
| 2 | 点"新建申请"，金额填 `4999` | 提交后进入"待主管审批" |
| 3 | 新建第二张，金额填 `5000` | 演示边界：正好 5000 要走财务 |
| 4 | 退出，用 `lijing` 登录 | 待办只剩研发部，市场部的单看不到 |
| 5 | 审批 4999 那张 → 通过 | 直接"已通过" |
| 6 | 审批 5000 那张 → 通过 | 变成"待财务复核"，**没有终审** |
| 7 | 退出，用 `wangfang` 登录 | 财务能看到两张待复核单（含市场部的大额单） |
| 8 | 复核通过 | 状态变"已通过" |
| 9 | 打开任意单据看时间线 | 每一步操作人、时间、意见都在 |
| 10 | 勾选"并发演示"，两个窗口同时点通过 | 一个成功，另一个提示"正在被其他人处理" |

**第 10 步是最有说服力的一步**：它证明系统在并发下不会产生重复审批。

## 6. 部署方案 A：CloudStudio（作业推荐）

CloudStudio 是云端 IDE，运行后把端口暴露成公网地址即可。不同版本界面略有差异，整体流程如下：

### 6.1 准备代码包

本地执行：

```bash
mvn clean package -DskipTests
```

得到 `target/purchase-approval-1.0.0.jar`（约 47 MB）。建议**只上传 jar**，避免在云端重复下载依赖。

### 6.2 新建工作空间

1. 登录 CloudStudio，新建工作空间，模板选择 **Java**（或空白 Linux 环境）。
2. 等待初始化完成，进入 Web IDE。

### 6.3 上传并运行

在 IDE 的终端中：

```bash
# 确认 Java 版本
java -version          # 需 17+

# 上传 jar 后（或用文件树拖拽上传）
java -jar purchase-approval-1.0.0.jar
```

若环境没有 JDK 17，先安装：

```bash
# Ubuntu/Debian 系
sudo apt update && sudo apt install -y openjdk-17-jdk
```

### 6.4 暴露公网端口

在 CloudStudio 的**端口/预览**面板中，把 `8080` 添加为可访问端口，平台会生成形如
`https://xxxx-8080.cloudstudio.work` 的公网地址。

打开该地址 → 出现登录页 → 部署成功。

> 注意：部分平台需要把应用监听在 `0.0.0.0`。本项目默认监听全部网卡，若访问不通，可在启动时显式指定：
> `java -jar app.jar --server.address=0.0.0.0`

### 6.5 提交作业时的建议

- 在报告里附上公网地址 + 一张访问截图（证明可远程访问）。
- 若平台休眠导致链接失效，提前录制一段演示视频作为兜底。

## 7. 部署方案 B：云服务器（阿里云/腾讯云轻量）

```bash
# 1. 服务器安装 JDK 17
sudo apt update && sudo apt install -y openjdk-17-jdk

# 2. 上传 jar
scp target/purchase-approval-1.0.0.jar root@<公网IP>:/opt/app/

# 3. 后台启动
cd /opt/app
nohup java -jar purchase-approval-1.0.0.jar > app.log 2>&1 &

# 4. 查看日志
tail -f app.log

# 5. 安全组放行 8080 端口（控制台操作）
```

访问 `http://<公网IP>:8080`。

**生产化建议**（作业不强制）：

- 前置 Nginx 反代 80/443，隐藏 8080
- 用 `systemd` 托管进程，避免 SSH 断开后退出
- 数据库换成 MySQL，`spring.datasource.url` 改指向 RDS
- 关闭演示开关：`--app.demo-mode=false`

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Port 8080 was already in use` | 端口被占用 | `--server.port=8081` 换端口，或结束占用进程 |
| 打包报 `Unable to rename ... jar` | 有进程正在运行该 jar | 先停止服务再打包 |
| 页面中文乱码 | 终端编码问题（不影响网页） | 启动加 `-Dfile.encoding=UTF-8` |
| 重启后数据全没了 | H2 是内存库 | 演示属正常；需要持久化改 `jdbc:h2:file:./data/purchase` |
| 登录提示令牌过期 | 服务重启导致内存令牌失效 | 重新登录即可 |
| 时间显示差 8 小时 | 后端返回 UTC，前端按本地时区渲染 | 检查浏览器时区 |
| CloudStudio 访问 404 | 端口未暴露或监听地址不对 | 用 `--server.address=0.0.0.0` 重启并检查端口面板 |

## 10. 配置项速查

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | 8080 | 服务端口 |
| `app.approval.finance-threshold` | 5000 | 财务复核金额阈值（含等于） |
| `app.demo-mode` | true | 是否允许 `X-Demo-Delay-Ms` 演示延迟，**生产置 false** |
| `spring.datasource.url` | H2 内存 | 改 MySQL 只需替换此项与驱动依赖 |
