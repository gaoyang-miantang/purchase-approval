# 操作手册

本手册覆盖三件事：**本地怎么跑起来**、**怎么演示**、**怎么部署到公网**。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17+ | 项目使用 Java 17 语法（record / switch 表达式） |
| Maven | 3.6+ | 或用 IDE 内置 Maven |
| Node.js | 18+ | 仅前端二次开发需要；只跑后端不需要 |
| 浏览器 | Chrome / Edge 最新版 | 界面使用现代 CSS（grid、backdrop-filter） |

> 数据库无需安装：默认使用 H2 内存库，启动即初始化演示数据。

## 2. 一键启动（推荐）

项目根目录执行：

```bash
bash start.sh        # Linux / macOS / CloudStudio
start.cmd            # Windows（双击）
```

脚本会自动：构建后端（如无 jar）→ 启动后端 8000 → 装前端依赖 → 启动前端 3000。

启动后：

| 服务 | 地址 |
| --- | --- |
| 前端 | <http://localhost:3000> |
| 后端 | <http://localhost:8000> |

> 端口与课程模板一致（后端 8000、前端 3000），`start.sh` 放在项目根目录，内部 `cd backend` / `cd frontend`。

## 3. 手动启动

**只跑后端（单 jar，已内嵌前端产物）**

```bash
cd backend
mvn clean package -DskipTests
java -jar target/purchase-approval-1.0.0.jar
```

看到 `Started PurchaseApplication in 3.2 seconds` 即成功，浏览器打开 <http://localhost:8000>。

**前后端分开跑（开发态）**

```bash
# 终端 1：后端
cd backend && mvn spring-boot:run

# 终端 2：前端
cd frontend && npm install && npm run dev
```

## 4. 前端开发模式（需要改界面时）

前端源码在 `frontend/`，构建产物输出到后端静态目录。

```bash
cd frontend
npm install          # 首次
npm run dev          # 开发服务器 http://localhost:3000，/api 自动代理到 8000

npm run build        # 产物输出到 ../backend/src/main/resources/static
```

修改前端后必须重新 `npm run build` 并重新打包 jar，改动才会体现在单 jar 部署里。

## 5. 演示动线（建议 5 分钟）

| 步骤 | 操作 | 讲解要点 |
| --- | --- | --- |
| 1 | 用 `zhangwei` 登录 | 员工只能看到自己的 5 张单，看不到市场部 |
| 2 | 点"新建申请"，金额填 `4999` | 提交后进入"待主管审批" |
| 3 | 新建第二张，金额填 `5000` | 演示边界：正好 5000 要走财务 |
| 4 | 退出，用 `lijing` 登录 | 待办只剩研发部，市场部的单看不到 |
| 5 | 审批 4999 那张 → 通过 | 直接"已通过" |
| 6 | 审批 5000 那张 → 通过 | 变成"待财务复核"，**没有终审** |
| 7 | 退出，用 `wangfang` 登录 | 财务能看到两张待复核单（含市场部的大额单） |
| 8 | 复核通过 | 状态变"已通过" |
| 9 | 打开任意单据看时间线 | 每一步操作人、时间、意见都在 |
| 10 | 勾选"并发演示"，两个窗口同时点通过 | 一个成功，另一个提示"正在被其他人处理" |

**第 10 步是最有说服力的一步**：它证明系统在并发下不会产生重复审批。

## 6. 部署方案 A：CloudStudio（课程推荐）

CloudStudio 是云端 IDE，注册赠送机时（课程文档写明：注册送 **50 机时**，规格 **CPU 4核8G**），运行后把端口暴露成公网地址即可。地址：<https://cloudstudio.net/>

### 6.1 准备代码

本项目已按课程模板组织，**根目录有 `start.sh`**，内部会自动 `cd backend` / `cd frontend`：

```
项目根/
├── start.sh
├── backend/     Spring Boot，端口 8000
└── frontend/    Vite，端口 3000
```

上传方式二选一：

1. **Git 导入**（推荐）：把项目推到 GitHub/Gitee，在 CloudStudio 里"导入仓库"。
2. **直接上传**：把整个 `purchase-approval/` 目录拖进 IDE 的文件树。

> 注意：`backend/target/`、`frontend/node_modules/` 不要上传（已被 `.gitignore` 排除）。
> 若云端没有 Maven，先在本地执行 `cd backend && mvn clean package -DskipTests`，再把 `backend/target/` 一起上传，`start.sh` 会跳过构建直接用现成 jar。

### 6.2 新建工作空间

1. 登录 CloudStudio → 新建工作空间。
2. 模板选 **Java** 或空白 Linux 环境（需要 JDK 17 + Node 18+）。
3. 等待初始化完成，进入 Web IDE。

### 6.3 环境检查

在 IDE 终端确认：

```bash
java -version     # 需 17+
node -v           # 需 18+
mvn -v            # 可选，没有也行（用预构建 jar）
```

缺失时安装（Ubuntu/Debian 系）：

```bash
sudo apt update
sudo apt install -y openjdk-17-jdk maven
# Node 建议用 nvm 安装 18+
```

### 6.4 一键启动

在**项目根目录**执行：

```bash
bash start.sh
```

脚本会依次完成：构建后端 → 启动后端 8000 → 等待就绪 → 安装前端依赖 → 启动前端 3000，并打印两个地址与演示账号。

### 6.5 暴露公网端口

在 CloudStudio 的**端口 / 预览**面板中，把 **3000**（前端）添加为可访问端口，平台会生成形如
`https://xxxx-3000.cloudstudio.work` 的公网地址；再按需把 **8000**（后端）也暴露，便于直接调接口。

打开前端地址 → 出现登录页 → 部署成功。

> 若访问不通，检查两点：① 启动时是否监听 `0.0.0.0`（本项目 `start.sh` 与 `vite.config.js` 已显式指定）；② 端口面板是否已添加该端口。

### 6.6 提交作业时的建议

- 在报告里附上公网地址 + 一张访问截图（证明可远程访问）。
- 若平台休眠导致链接失效，提前录制一段演示视频作为兜底。
- CloudStudio 按机时计费，演示完记得**停止工作空间**，避免机时耗尽。

## 7. 部署方案 B：云服务器（阿里云/腾讯云轻量）

```bash
# 1. 服务器安装 JDK 17
sudo apt update && sudo apt install -y openjdk-17-jdk

# 2. 上传 jar
scp backend/target/purchase-approval-1.0.0.jar root@<公网IP>:/opt/app/

# 3. 后台启动
cd /opt/app
nohup java -jar purchase-approval-1.0.0.jar > app.log 2>&1 &

# 4. 查看日志
tail -f app.log

# 5. 安全组放行 8000 端口（控制台操作）
```

访问 `http://<公网IP>:8000`。

**生产化建议**（作业不强制）：

- 前置 Nginx 反代 80/443，隐藏 8000
- 用 `systemd` 托管进程，避免 SSH 断开后退出
- 数据库换成 MySQL，`spring.datasource.url` 改指向 RDS
- 关闭演示开关：`--app.demo-mode=false`

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Port 8000 was already in use` | 端口被占用 | `--server.port=8001` 换端口，或结束占用进程 |
| 打包报 `Unable to rename ... jar` | 有进程正在运行该 jar | 先停止服务再打包 |
| 页面中文乱码 | 终端编码问题（不影响网页） | 启动加 `-Dfile.encoding=UTF-8` |
| 重启后数据全没了 | H2 是内存库 | 演示属正常；需要持久化改 `jdbc:h2:file:./data/purchase` |
| 登录提示令牌过期 | 服务重启导致内存令牌失效 | 重新登录即可 |
| 时间显示差 8 小时 | 后端返回 UTC，前端按本地时区渲染 | 检查浏览器时区 |
| CloudStudio 访问 404 | 端口未暴露或监听地址不对 | 用 `--server.address=0.0.0.0` 重启并检查端口面板 |

## 10. 配置项速查

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | 8000 | 服务端口 |
| `app.approval.finance-threshold` | 5000 | 财务复核金额阈值（含等于） |
| `app.demo-mode` | true | 是否允许 `X-Demo-Delay-Ms` 演示延迟，**生产置 false** |
| `spring.datasource.url` | H2 内存 | 改 MySQL 只需替换此项与驱动依赖 |
